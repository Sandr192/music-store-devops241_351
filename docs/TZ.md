# Техническое задание: Музыкальный магазин

## 1. Назначение системы
Система представляет собой веб-приложение для учета музыкальных дисков, управления каталогом исполнителей, оформления продаж и отслеживания остатков на складе.

## 2. Категории пользователей
- **Гость**: просмотр каталога, поиск по жанрам и исполнителям.
- **Покупатель**: оформление заказов, просмотр истории покупок.
- **Администратор**: управление каталогом (добавление/редактирование альбомов и музыкантов), просмотр отчетов по продажам.

## 3. Основные сценарии
1. Администратор добавляет нового музыканта и его альбом в каталог.
2. Покупатель выбирает диск, добавляет в корзину и оформляет покупку.
3. Система проверяет остаток на складе и списывает его при успешной продаже.

## 4. Бизнес-правила (Ограничения)
- Нельзя продать диск, если его остаток на складе равен 0.
- Цена диска не может быть отрицательной.
- Продажа должна быть атомарной (если списание остатка не удалось, продажа не создается).

## 5. Сущности (Предварительная схема)
- `Musician` (Музыкант): id, имя, страна.
- `Album` (Альбом): id, название, год выпуска, цена, остаток, musician_id.
- `Genre` (Жанр): id, название.
- `Sale` (Продажа): id, album_id, количество, итоговая сумма, дата.

## 6. Функциональные требования

### Музыканты
- Добавление нового музыканта (имя, страна).
- Просмотр списка всех музыкантов.
- Просмотр информации о конкретном музыканте.
- Редактирование и удаление музыканта (если у него нет альбомов).

### Жанры
- Добавление нового жанра.
- Просмотр списка жанров.
- Редактирование и удаление жанра.

### Альбомы
- Добавление нового альбома (название, год, цена, остаток, музыкант, жанры).
- Просмотр каталога альбомов.
- Просмотр подробной информации об альбоме.
- Редактирование и удаление альбома (если по нему нет продаж).
- Фильтрация альбомов по музыканту и жанру.

### Продажи
- Оформление продажи альбома с указанием количества.
- Проверка остатка на складе при продаже.
- Автоматическое списание остатка после успешной продажи.
- Расчёт итоговой суммы продажи.
- Просмотр истории продаж.

### Авторизация
- Регистрация пользователя (email, пароль).
- Вход в систему по email и паролю.
- Выдача JWT-токена после входа.
- Разграничение прав: роль `admin` управляет каталогом, роль `user` оформляет покупки.

### Служебные функции
- Эндпоинт `GET /health` для проверки работоспособности.
- Проверка подключения к БД в healthcheck.
- Swagger-документация на `/docs`.
- Возврат корректных HTTP-кодов при ошибках (400, 401, 403, 404, 409).
