## 🔐 Правила безопасности

- Приложение **не запускается от root** — используется системный пользователь `appuser`.
- Вход по SSH — только по ключам (`PermitRootLogin no`, `PasswordAuthentication no`).
- Секреты (пароль БД, JWT-ключ) хранятся в файле `.env`, который **не коммитится** в Git.
- В репозитории есть только `.env.example` — шаблон без реальных значений.
- Пользователь `appuser` имеет минимально необходимые права на файлы проекта.

## 🔥 Firewall (ufw)

### На db-server

```bash
sudo ufw allow 22/tcp
sudo ufw allow from 10.0.2.20 to any port 5432
sudo ufw --force enable
sudo ufw status verbose
```

### На app-server

```bash
sudo ufw allow 22/tcp
sudo ufw allow 8000/tcp
sudo ufw --force enable
sudo ufw status verbose
```

## 📋 Скрипты

### `scripts/provision.sh`

Первичная настройка сервера приложения:
- обновление системы,
- установка базовых пакетов (Python, Git, ufw),
- создание системного пользователя `appuser`,
- клонирование репозитория проекта,
- создание виртуального окружения и установка зависимостей,
- настройка firewall (ufw).

### `scripts/deploy.sh`

Обновление приложения:
- `git pull` — получение свежего кода из `main`,
- установка зависимостей через `pip`,
- применение миграций Alembic (`alembic upgrade head`),
- перезапуск systemd-службы `music-store`.

## 🔄 Восстановление после аварии

### Если упала БД

1. Проверить статус:
   ```bash
   sudo systemctl status postgresql
   ```
2. Перезапустить:
   ```bash
   sudo systemctl restart postgresql
   ```
3. Проверить приложение — при недоступной БД `/health` должен возвращать `503 Service Unavailable`:
   ```bash
   curl http://app-server:8000/health
   ```

### Если упало приложение

1. Проверить статус службы:
   ```bash
   sudo systemctl status music-store
   ```
2. Посмотреть последние 50 строк логов:
   ```bash
   sudo journalctl -u music-store -n 50
   ```
3. Перезапустить службу:
   ```bash
   sudo systemctl restart music-store
   ```

## ✅ Проверки для защиты

1. **Перезагрузка VM** → службы автоматически запускаются.
2. **Остановка БД** (`sudo systemctl stop postgresql`) → приложение выдаёт ошибку в `/health`.
3. **Проверка недоступности БД с постороннего узла**:
   ```bash
   # С app-server (должно работать):
   nc -zv 10.0.2.10 5432

   # С Windows-хоста (должно НЕ работать):
   nc -zv 10.0.2.10 5432
   ```
4. **Изменение параметра службы** → восстановление (изменить `ExecStart`, сделать `daemon-reload`, `restart`).
5. **Процессы, порты, журналы** — `htop`, `ss -tlnp`, `journalctl`.
